## 3. Methodology

1. Pre-workshop: extracted full hazard, hazardous_situation, harm, and residual data from all 97 YAML files and 94 FMEA rows into structured JSON for parallel review.
2. Atlas traceability matrix was refreshed live (73 User Needs, 221 Design Inputs, 39 Design Outputs, 39 Verification Tests, 1 Validation Test) before reviews started.
3. Six review roles operated concurrently, each producing a schema-controlled JSON finding file.
4. Findings were merged mechanically: Clinical Safety Lead results set the initial severity/probability/detectability; specialists (Security, Accessibility) set residual risk values; UN/Traceability Auditor resolved open UN and DI links.
5. Conflicts resolved by the stricter assessment taking precedence (e.g. Security flagging "unacceptable" overrides Safety Lead "acceptable").

## 6. Production-blocking residual risks

Two risks carry **unacceptable** residual risk per the IG/Security Officer review.

### R-LEO-AI-131 - Audit trail tampering after creation

- Hazard category: security_breach (STRIDE: Tampering, Repudiation)
- Regulatory hook: NHS DCB0129 clinical safety case relies on audit integrity; UK GDPR Article 30 Record of Processing; ISO 27001 A.12.4
- Missing control: audit storage is NOT immutable at storage layer; append-only relies on application logic alone
- **Required action (blocking):** implement WORM storage OR hash-chain verification layer; add tamper-detection alarm to monitoring
- Target owner: IG Lead + Platform Engineering

### R-LEO-AI-154 - Real patient data in sandbox environment

- Hazard category: security_breach
- Regulatory hook: UK GDPR Article 5(1)(c) data minimisation; NHS DCB0160 deployment management
- Missing control: no automated de-identification gate between production and sandbox; no logical isolation guarantee
- **Required action (blocking):** enforce de-identification at copy boundary; add job-level assertion that sandbox environments cannot hold raw clinical text; add detective control to scan sandbox tenants daily
- Target owner: IG Lead + DevOps

## 7. DI gaps requiring new Design Input artefacts

The Software/DI Auditor identified 10 risks where current Mitigating Design Inputs do not fully cover the hazard. The listed `missing_controls` must become new DIs (or extensions to existing DIs).

Top recurring themes:

1. Drift-job execution monitoring (separate from drift detection itself)
2. Two-reviewer gate for bulk imports (currently only single-entry path)
3. COI (conflict-of-interest) detection for privileged users
4. Audit immutability + tamper detection
5. Deployment-gate controls for NICE and SNOMED ingests
6. Standardised aria-live usage across async status surfaces
7. Forced-colors mode (Windows High Contrast) in CI accessibility sweep
8. Split Flesch-Kincaid CI gate: FK <=6 for patient-reachable copy, FK <=9 for staff

All 10 gap-flagged risks are listed in `_workshop_03_di_audit.json` under `summary.risks_needing_new_di`.
